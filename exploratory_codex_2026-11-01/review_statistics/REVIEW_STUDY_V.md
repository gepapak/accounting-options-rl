## Findings that affect the interpretation

1. **Major — the tested cheap baseline succeeds, including zero-start training.** RUIN5 has mean X=0 and E=18.9679127871 in A (90.78% of oracle) and E=17.1867444277 in C (86.64%). RUIN25 also meets both in A, but in C its E=4.17573232324 and E from zero=0.03316560840. This directly defeats VA5/VC6. “A penalty must either leave gambling or destroy the edge” is not a conclusion available from these results. Locations: `aggregate_v.py:76–86`; `rewards_v.py:59–67`; the pre-registration's theory discussion is a prior argument, not an established result. Recommendation: explicitly retain the successful RUIN5 counterexample in any comparison or broad claim.

2. **Major — PMR's measured success does not establish exact conditional unbiasedness.** The code pools *every* favourable nonzero step, not an independently certified uncensored subset (`rewards_v.py:85–92`). Under the mathematical common-floor model the contributed value is `max(m,(tau+C)/|q|)`, which can exceed m. Excluding the current observation avoids direct same-step self-inclusion; it does not remove that censoring bias, finite-pool error or dependence of the pool on visited states. The implementation matches the registered estimator; this is a theory/claim qualification, not a code bug or reason to invalidate the empirical verdicts. The generic `twin_reward/twin_reward.py` wrapper has its own per-wrapper pool and is not the shared-pool implementation used in V. Recommendation: the theory reviewer must state the extra conditions for any exact expected-reward claim; do not describe the empirical 31/32 count as a proof of that claim.

3. **Scope confirmation — VD1 is accuracy of a 100-episode mean, not a pathwise or individual-week guarantee.** This is correctly defined in `aggregate_v.py:44`, `:169–171` and `run_v.py:150–162`; the parent reviewer also confirms the captions already qualify it. Recomputed maximum single-week TIR errors are **3.191665625** edge and **3.010359375** placebo; the largest agent-wise mean absolute weekly errors are 0.398450119 and 0.632418513. Thus “within 0.4 points” needs “of each policy's 100-week mean.” The audit is a same-policy, same-simulator replay with evaluation-time twins, not off-policy evaluation or an independently calibrated confidence interval. This is not an additional manuscript defect where the qualification is already present.

4. **Design limitation, not an analysis error — Part B is an unpaired cross-study comparison conditional on common test windows.** PMR has eight new learner seeds; each T comparator has ten. The code resamples 8 and 10 independently, as registered (`aggregate_v.py:60–63`, `:131–143`); it does not falsely pair seeds. Shared market/test windows remove one source of mismatch but do not create independent new market replications or identify a reward-only causal effect across every training implementation. PMR exceeding trained ORACLE does not mean exceeding the true booked-optimal policy. A/C also use nominally matched learner seeds, whereas the registered inference treats arms as unpaired; no replacement paired analysis was used to change decisions.

5. **Design limitation — three weights are not the whole class of cheap remedies.** The downward MV grid change is disclosed (`PREREGISTRATION_V.md:30–40`) and makes the smallest tested weight less destructive. C is an intentionally difficult, pilot-informed distribution for a penalty paid only on entry into zero. However strengths 1 and 5 were added before registered C runs, and 5 succeeds: this is not a demonstrably weak grid within the stated family. The result does not test a penalty at every zero-equity step, position/forgiveness-proportional penalties, termination, or constrained/Lagrangian learning. A forgiven-loss penalty has extra information; termination changes the task. The existing files can compare the tested trained agents and audit their returns, but cannot establish how agents would train under those untested rewards. The registered `r-lambda*r*r` is a quadratic-utility/mean-variance-style surrogate, not every implementation of mean-variance optimization.

## Implementation and record checks

- **PMR order and sharing:** one `MagnitudePool()` per job (`run_v.py:66`) is captured by the eight environment factories (`:71–88`). It starts at total=0,n=0 for every run (`rewards_v.py:29–39`); it is deterministic rather than separately randomly seeded. Each environment computes its actual capped q using the same source formula as `EdgeEnvT.step`, reads the realized exogenous sign, steps, uses the old pool mean, and only then adds its draw. Sequential DummyVecEnv slots can use earlier slots' newly completed draws, but never their own current draw. No ledger, pnl, threshold or accounting-rule field is read by the reward function. Its explicit access includes own executed position/cap, own cost and realized sign; “reward channel alone” must not erase these inputs.
- **RUIN/MV:** raw rewards are percent of K0. RUIN subtracts 1/5/25 such points only when reported equity crosses from positive to nonpositive. MV subtracts the registered lambda times the square of the raw percent reward. Both operate before `VecNormalize(norm_reward=True,gamma=.99)` (`run_v.py:81–89`). Thus they have the same normalization pipeline, not identical normalized penalty magnitudes; reward clipping/normalization is not a silent conversion of lambda into EUR.
- **C:** the 0.5 zero-start coin is implemented only when e0 is absent (`rewards_v.py:46–50`). Test/audit always use `EdgeEnvT` and explicitly set e0 (`run_v.py:106–130`), so C changes training starts, not the main evaluation distribution. The random mixture is 50% in law, not a promise of exactly half of the realized episodes. The first reset draws that coin before forwarding an explicit reset seed; later ordinary resets use the seeded environment RNG. This is a minor reset-API reproducibility caveat, not evidence that the registered mixture or results are wrong.
- **Twin integrity:** the source step mutates scalar ledger/equity/time fields but does not mutate its market arrays (`envs_t.py:94–110`). The shallow-copy twin therefore preserves the original state in this implementation; the sign override affects only the twin. Audit clones are used only after training; Part C's TIR training arm intentionally uses twins during training (`run_v.py:77–78`, `:137–145`). This cannot be generalized to arbitrary mutable simulator state without checking its clone contract.
- **Truth and replay:** booked audit values are direct `(env.ledger-env.e0)/K0*100`, not the TIR/PMR estimate (`run_v.py:150`). The source separately replays the same seeded tests and asserts both booked and reported means (`:169–174`). All saved 100-episode arrays, estimator means, MAEs and those replay-summary assertions reproduce for all 144 runs. There are no saved transition traces or model weights in these JSON outputs, so this review does not pretend to independently replay the complete trajectories or re-evaluate the policies.
- **Run roster and failure semantics:** exact A72+B16+C56 with distinct registered identities and steps=1,000,000; smoke's subfolder is excluded by the top-level result glob (`aggregate_v.py:34`). Every summary scalar checked in `runs_v.csv` equals raw JSON exactly. `run_v.py:225–227` logs worker exceptions but returns process exit code0, and `:54–55` skips an existing output without validating it. These are durability weaknesses for a future runner, not evidence of a missing/replaced run here: all 144 files are present, valid, correctly identified and complete at the saved-data level. Requested timesteps are logged; PPO's usual full-rollout rounding is not logged as an actual transition count.

## Key counts and useful falsifiers

- PMR has X=0 in **31/32**, not 32/32. Its A seed151 has X=0.5 and E=-10.0662497797, causing VA3's lower bound to fail.
- PLAIN has X>0 in **15/16** A/C learners. X is the specified 16-probe max-requested-leverage score, not observed test-trading frequency or ruin probability (`run_v.py:100–104`).
- The 28 VD2 agents comprise **15 PLAIN, 11 RUIN1, 1 PMR and 1 MV1**. VD2 is not restricted to reported-reward PLAIN policies.
- Part B's PMR returns are highly concentrated: all eight DK2 returns are identical; DK1M has two numerically distinct returns and two full probe maps. All16 PartB agents' probes use only leverage ±4. `envs_b.py:37` defines Q1=.25MWh, so this is nominal |q|=1MWh before liquidity clipping, not q=4MWh (maximal leverage16 would be4MWh). C PMR has one full probe map. The files support convergence to essentially the same simple signal policy/performance, not a proof of global optimality or a richer learned decision advantage over that rule. Exact equality to an independently evaluated fixed-rule benchmark belongs to the parent's separate check.
- Audit SPR max mean errors: 5.771938727 edge/2.170911669 placebo; PMR: 10.189290316/2.842787037. These exploratory quantities do not replace the registered TIR audit criterion.

The three logged post hoc edge comparisons also reproduce, independently using the saved agent E values: PMR>RUIN5 A p=0.112557157532443; PMR>RUIN5 C p=0.0423724762113288; TIR>RUIN5 C p=0.192709116184115.
